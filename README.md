## Что изменилось в 1.1.0

Добавлены **17 площадок и авторов, 18 отправных публикаций**: российские профильные форумы,
ВК, Instagram, TikTok и подходящие зарубежные сообщества. В машиночитаемом реестре есть адреса,
тематика, поисковые слова, регион, независимость от бренда и статус проверки.
Это стартовые источники, не автоматически прочитанные страницы или найденные сейчас тренды.

**Перед контент-планом и статьёй обязательно исследование рынка.** Агент ищет реальные проблемы,
разбирает попытки решения, альтернативы, незакрытые потребности и динамику. Для плана нужны
прочитанные внешние материалы минимум двух независимых источников, включая российский.
Попытки работы с форумами, ВК, Instagram и TikTok фиксируются; недоступный ресурс отмечается честно.

`new`, `validate`, `export` и `approve` блокируют отсутствие исследования, отчёт старше 7 дней,
изменённые доказательства и неподтверждённый план. Описание ролика не считается просмотром,
перепечатка не становится независимым сигналом. Без измерений тренд остаётся `not_measured`.

## Запуск

```bash
git clone https://github.com/f2re/mad-seo-skill.git
cd mad-seo-skill
python mad.py init
python mad.py doctor
python mad.py sources
python mad.py search-plan
python mad.py research-new market-first --days 30
```

Откройте папку в среде ИИ и поручите:

> Используй mad-content. Сначала выполни mad-research по реестру сообществ: найди реальные проблемы,
> попытки решения и альтернативы. Проверь документированное решение MAD-auto. Подготовь исследование,
> пройди research-check и plan-build, затем напиши статью по пункту плана. Делегируй независимые проверки.
> Не выдумывай чтение закрытых источников, рост спроса и результаты испытаний. Не утверждай от имени человека.

После фактического поиска и заполнения `content/research/market-first/research.json`:

```bash
python mad.py research-check market-first
python mad.py plan-build market-first
python mad.py new bridge-ports --problem com-pair --research market-first
```

Пустой шаблон не проходит проверку. Текст пишет модель в выбранной среде; Python создаёт задания,
проверяет файлы и формирует план/экспорт. Он не выполняет интернет-поиск и не имитирует работу агента.
`topics` показывает гипотезы; это не замена проверенного контент-плана.

## Устройство процесса

| Этап | Результат |
|---|---|
| Поиск по сообществам | Прочитанные проблемы, попытки решения, исходы; недоступные источники указаны |
| Анализ рынка | Альтернативы, незакрытые потребности, измеренная динамика либо её отсутствие |
| Проверка MAD-auto | Проблема связана с документированной возможностью и ограничениями |
| Контент-план | JSON и Markdown: тема, источники, польза, приоритет, действие new/update |
| Статья | Ответ, применимость, подготовка, шаги, ожидаемый результат, ошибки и ограничения |
| Приёмка | Независимые проверки и утверждение человеком конкретного хеша |
| Экспорт | Локальный пакет CMS, не публикация на рабочий сайт |

Девять ролей: координатор, исследователь, инженер решения, проверяющий факты, редактор,
поисковый редактор, арт-директор, проверяющий безопасность, аналитик. Восемь сценариев
и 42 файла интеграции для Codex, Claude Code и Antigravity. Максимум три проверки параллельно.
Описание роли не доказывает её запуск; отсутствие субагентов отражается в отчёте.

## Предметная база

[13 начальных проблем](knowledge/problems.json) связаны с [11 возможностями](knowledge/capabilities.json)
WiFi OBD2, ECU Logger, Dashboard и WiFi AFR. Эти направления основаны на документации,
а не на выдуманной статистике спроса. Для новой проблемы сначала нужны внешние наблюдения
и подтверждённое решение, затем расширение базы и knowledge-check.

Источники — [knowledge/sources.json](knowledge/sources.json), нерешённые противоречия —
[knowledge/conflicts.json](knowledge/conflicts.json). Неизвестные версии и совместимость
не заполняются по сходству названия. Для DSG и других недостаточно документированных устройств
технические обещания требуют отдельной подробной базы.

## Приёмка и экспорт

```bash
python mad.py validate bridge-ports
python mad.py export bridge-ports
python mad.py review-template bridge-ports
python mad.py status bridge-ports
# Только после проверки и явного поручения человека на текущую версию:
python mad.py approve bridge-ports --confirm 'bridge-ports@ПОЛНЫЙ_SHA256'
python mad.py export bridge-ports --approved
```

Экспорт содержит HTML, Markdown, JSON для CMS, TechArticle/BreadcrumbList и изображения.
Предпросмотр всегда noindex. Нельзя гарантировать индексацию или цитирование всеми нейросетями.
Актуальное исследование и план включены в контроль версии; их изменение отзывает прежнюю приёмку.

Старые задания требуют `research-link <slug> --research <id>` после настоящего исследования и нового плана.
[Архивный пример COM-моста](examples/article-demo/pack.json) не получает исключений и не содержит
фиктивного исследования рынка. [Передача в CMS](docs/PUBLISHING.md).

## Аналитика и установка

```bash
python mad.py analytics-import --provider google --file real-metrics.csv
python mad.py analytics-report
python mad.py install --target ../mad-editorial --dry-run
```

В этой версии аналитика — нормализованный CSV и локальная база. OAuth и API публикации нового сайта
не подключены. Установка не перезаписывает изменённые пользовательские файлы.
Рабочие статьи, отчёты, заметки и аналитика исключены из git. Commit/push кода не публикует статьи.
