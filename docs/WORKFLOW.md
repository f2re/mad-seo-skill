# От затруднения пользователя к статье

Обязательные входные документы: [исследование рынка](RESEARCH-FIRST.md) и [каталог площадок](COMMUNITIES.md).
С версии 1.1.0 исследование проверяется программно, а не только описывается в инструкции агенту.

| Этап | Исполнитель | Результат и условие перехода |
|---|---|---|
| Границы задачи | Координатор | Ниша и проблема относятся к устройствам MAD-auto |
| Поиск | Исследователь | Реальные запросы, прочитанные материалы, даты, попытки решения и исход |
| Анализ рынка | Аналитик | Альтернативы, незакрытые потребности, динамика или отсутствие измерений |
| Проверка решения | Инженер решения | Возможность MAD-auto подтверждена первичной документацией |
| Проверка исследования | CLI + приёмщик | research-check: актуальность, независимость, доступ, связанные доказательства |
| Контент-план | Координатор | plan-build: источники, польза, ограничения, new/update вместо дубля |
| Задание | Координатор | new --research: тема есть в проверенном плане |
| Доказательства статьи | Проверяющий факты | Прочитанные источники, связанные технические утверждения, точная применимость |
| Черновик | Автор | Ответ, подготовка, шаги, результат, ошибки, ограничения без выдуманного опыта |
| Иллюстрации | Арт-директор | Реальный интерфейс нужной версии или проверенная схема, права и приватность |
| Независимая проверка | Инженер, редактор, поисковый редактор | Замечания по конкретным местам; автор не принимает сам себя |
| Автопроверка | CLI | validate: нет блокирующих ошибок, но это не доказательство истинности |
| Приёмка | Человек | Предпросмотр, замечания и текущий хеш; высокие риски требуют инженера |
| Экспорт | Координатор | Локальный пакет CMS, без отправки на сайт |
| Измерение результата | Аналитик | Реальные выгрузки и проверяемые предложения изменений |

Этапы не равны обязательному числу вызовов модели. Исследование рынка и проверку возможностей можно
делегировать параллельно; текст появляется только после их сопоставления. Максимум три задачи параллельно,
два цикла исправлений. Неустранённый недостаток переводит материал в blocked, а не маскируется уверенным текстом.

## Файлы

`content/research/<id>/research.json` — проверенные попытки доступа, наблюдения, анализ и кандидаты тем.
`evidence/` — разрешённые заметки и небольшие выдержки с SHA256 и локатором.
`content/plans/<id>.json` и `.md` — план из актуального исследования, не произвольно изменяемый список.
`content/jobs/<slug>/brief.json` — проблема, связь с исследованием, применимость, риск и SEO-действие.
`sources.json`, `claims.json`, `pack.json` — доказательства, утверждения и материал.
`review.json` и `approval.json` — человеческая приёмка конкретной версии.

## Применимость

Режим general объясняет документированный принцип и не обещает конкретную совместимость.
Режим exact требует ЭБУ, его ПО, адаптер, прошивку, приложение, версию и платформу.
Документированное не означает испытанное. Неизвестные поля не заполняются по похожей модели.
Высокий риск и заявления о собственном испытании требуют человека-инженера на эту версию.

## Делегирование и версия

В задании проверяющему укажите цель, пути, источники и критерии отказа. Ответ: verdict,
findings с конкретным местом, source_urls, required_changes, not_checked. Все изменения собирает координатор.
Нет механизмов субагентов — явно укажите последовательную проверку той же моделью.

Хеш утверждения охватывает материал, источники, медиа, конфигурацию, инструкции, исследование и план.
Правка доказательства или устаревшее исследование требует повторной проверки. Это контроль версии,
не удостоверение личности и не гарантия правдивости. Старое задание связывается через research-link;
архивные примеры не получают исключений.
