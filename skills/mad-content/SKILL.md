# mad-content

Прочитайте AGENTS.md, docs/WORKFLOW.md и docs/RESEARCH-FIRST.md.
Нельзя начинать со статьи. Сначала актуальное исследование рынка: проблемы, реальные попытки решения,
альтернативы, тренды или явное отсутствие измерений, ограничения выборки и проверенное решение MAD-auto.
Нет готового исследования — выполните mad-research и mad-plan, а не сочиняйте тему.

```bash
python mad.py research-check <id>
python mad.py plan-build <id>
python mad.py new <slug> --problem <problem-id> --research <id>
```

Пишите только по пункту проверенного плана. Заполните brief, источники и claims, затем резюме
и шесть обязательных разделов pack. Покажите ожидаемый результат и ветку действий при неудаче.
Неизвестные версии, отзывы и замеры не выдумывать. Технические возможности подтверждаются первично.

Делегируйте техническую, редакционную и поисковую проверки отдельным реально доступным агентам.
Выполните validate и export, покажите все замечания. Человек утверждает конкретный хеш;
модель не подставляет имя инженера и не заполняет mode: human.
Верните существующие пути и ограничения. Commit/push выполняется только в явно порученной задаче
изменения репозитория после проверок; размещение статьи на сайте — отдельное действие.
