# Сначала исследование рынка, затем план и статья

## Работа без скрытой автоматизации

Агент использует реальные доступные средства веб-поиска, браузера или разрешённого экспорта
площадки. CLI не вызывает модель, не читает соцсети и не утверждает, что поиск был выполнен.
Проверка машинная: полнота отчёта, связанные источники, контроль версий и актуальность.
Истинность заметки и факт просмотра видео всё равно проверяют исследователь и отдельный приёмщик.

```bash
python mad.py init
python mad.py sources
python mad.py search-plan
python mad.py research-new market-first --days 30
```

Откройте `content/research/market-first/research.json`. До заполнения этот файл не проходит проверку.
`knowledge/community-sources.json` содержит 17 источников: российские профильные форумы, ВК,
Instagram, TikTok и подходящие зарубежные площадки. [Таблица и отправные ссылки](COMMUNITIES.md).
Их присутствие в реестре не означает актуальную проверку, просмотр видео или подтверждение спроса.

## Что собрать

В `coverage` для реально проверенных источников запишите `source_id`, фактический `query`,
`checked_at` (дата UTC), результат в `note` и `status`: `read`, `metadata_only`, `blocked`.
Нет попытки — `not_checked`. Обязательны попытки по forum/vk/instagram/tiktok, но не обход всех
17 источников при каждой узкой теме. Недоступность одной соцсети не требует обходить её ограничения.
Она фиксируется с причиной, после чего исследуются другие открытые материалы.

Для отчёта с темами нужны прочитанные материалы минимум двух независимых внешних источников,
включая российский. Собственные каналы не увеличивают независимость. Страна unknown остаётся
неизвестной; русскоязычный украинский автор не становится российским. Источник автора/площадки
проверяется по URL, а не по придуманному названию в поле.

Сохраните разрешённую заметку или небольшой фрагмент, не зеркало чужого сайта:

```bash
python mad.py research-evidence market-first --key forum-check --file reviewed-note.txt
```

Команда возвращает `path` и `sha256`. Добавьте `locator` — точный раздел, сообщение или отметку
времени видео. Объект `evidence` используется в coverage, observations и solution_checks.
Для blocked заметка описывает не содержимое закрытого источника, а реально выполненную попытку
и её результат. Не публикуйте логины, токены, VIN, личные сообщения и серийные номера.

## Структура наблюдения

```json
{
  "id": "observation-id",
  "source_id": "turbobazar",
  "url": "https://turbobazar.ru/threads/34653/",
  "status": "read",
  "read_at": "дата фактического чтения",
  "occurred_at": null,
  "problem_id": "com-pair",
  "problem": "Что именно не получается у пользователя",
  "attempted_solution": "Что он уже пробовал; неизвестное так и обозначить",
  "outcome_status": "unresolved",
  "outcome": "Решение не подтверждено автором",
  "independence_key": "идентификатор исходной ветки, не перепечатки",
  "public_or_redacted": true,
  "evidence": {"path": "путь из research-evidence", "sha256": "хеш файла", "locator": "номер сообщения"}
}
```

Это описание полей, не готовый импорт. `occurred_at` не заменяется датой чтения. Просмотренная
старая ветка остаётся старой проблемой. Статусы результата: author_reported, suggested, unresolved,
not_verified. «Автор сообщил об успехе» не означает, что MAD-auto повторила испытание.
`metadata_only` помогает найти материал, но не допускается как основание пункта плана.

## Анализ и выбор тем

Заполните analysis: summary (какие проблемы найдены), alternatives (чем уже пытаются решить),
unmet_needs (что остаётся неудобным), growth_assessment (есть ли доказанный рост), sample_limits
(пропуски, архивы, закрытые площадки, смещение выборки). Неизмеренный рост явно обозначается.

Для каждой записи candidates нужны problem_id, observation_ids, reader_value, priority_reason,
solution_checks. Каждая solution_checks содержит capability_id, URL первичной документации,
checked_at и evidence. Кандидат должен соответствовать проблеме и реальной возможности из knowledge.
Новая проблема сначала регистрируется с источниками и ограничениями; общая авто-новость не подходит.

Без `trend_measurement` в плане автоматически сохраняется `not_measured`. Для численного тренда
нужны соседние равные полные окна одного источника, единицы и охвата. `trend_evidence` закрепляет
JSON этих измерений; значения должны совпадать с trend_measurement.
Синтетические данные запрещены. Два обсуждения сами по себе — не рост рынка и не частотность запроса.

## План и допуск к статье

```bash
python mad.py research-check market-first
python mad.py plan-build market-first
python mad.py new bridge-ports --problem com-pair --research market-first
```

`plan-build` создаёт `content/plans/market-first.json` и читаемый Markdown. В плане сохраняются
источники, проблемы, решение, обоснование приоритета, статус спроса, ограничения и действие
new/update. При наличии прежней страницы предлагается update. При отсутствии подтверждённых тем
создаётся пустой план; статья по нему не разрешена. `topics` по-прежнему показывает гипотезы,
но не заменяет этот план.

Политика актуальности — 7 дней, окно поиска — до 90 дней. Это редакционные ограничения, не
статистическая гарантия. Повторно используются только неустаревшие исследования подходящей темы;
один отчёт может обосновывать несколько статей. Нельзя просто обновить дату без повторного чтения.

Изменение отчёта, заметки, реестра, возможности или плана требует повторной проверки. `new`
не создаёт статью без плана, а `validate`, экспорт и утверждение повторно проверяют связь.
Хеш утверждения охватывает исследование и план. Старые задания не получают исключений:

```bash
python mad.py research-link existing-job --research market-first
python mad.py validate existing-job
```

Привязка нового исследования требует повторной редакторской/человеческой приёмки, а не повторного
использования старого approval. Архивный article-demo поставляется без выдуманного исследования.

## Commit и push

По явному поручению на изменение репозитория: проверьте diff, тесты и документацию, закоммитьте
только согласованные файлы, выполните push без force и проверьте удалённый SHA/CI. Рабочие отчёты,
evidence, сырая переписка и аналитика остаются в исключённых из git каталогах. Публикация статьи
в системе управления сайтом — отдельное действие после утверждения, не побочный эффект push.
